# AGENTS.md

## Commands

- `pnpm dev` — dev server at `http://localhost:3000` (admin at `/admin`). pnpm is required (`packageManager: pnpm@11.0.8`); `pnpm-lock.yaml` **is** committed, so use `pnpm install --frozen-lockfile` in CI. Inside a parent workspace, use `pnpm ii` (runs with `--ignore-workspace`).
- `pnpm lint` / `pnpm lint:fix` — ESLint.
- **There is no `typecheck` script.** Use `pnpm exec tsc --noEmit`. (`pnpm build` also typechecks, but it needs a database.)
- `pnpm test:int` — Vitest integration tests (`tests/int/**/*.int.spec.ts`).
- `pnpm test:e2e` — Playwright; it starts `pnpm dev` itself (`reuseExistingServer: true`, so an already-running dev server is reused).
- `pnpm test` — runs int, then e2e.
- `pnpm quality:all` — a11y (axe + pa11y), Lighthouse, JSON-LD schema validation and `llms.txt`. **Needs a running dev server.**

Verification order: `pnpm lint` → `pnpm exec tsc --noEmit` → `pnpm test:int`.

Run a single test:

```bash
pnpm exec vitest run tests/int/i18n.int.spec.ts
pnpm exec playwright test tests/e2e/frontend.e2e.spec.ts
```

## CI

`.github/workflows/quality-gates.yml` runs on PRs to `main`/`develop` and pushes to `main`:

- `lint-and-typecheck` — no database needed.
- `build` — applies migrations first, then builds.
- `tests` — integration + e2e against a Postgres 16 service.
- `frontend-quality` — boots one dev server and runs schema, `llms.txt`, axe, pa11y and Lighthouse against it.

**The frontend checks must share a single job.** GitHub runners are ephemeral, so a "dev-server" job that a later job `needs:` does not share a machine — `localhost:3000` will not exist there. Do not split these back apart.

## Tests need a real database

Both suites boot Payload against `POSTGRES_URL` from `.env`; nothing is mocked or fixture-backed. `.env` must exist first (`cp .env.example .env`). `tests/e2e/admin.e2e.spec.ts` seeds then deletes a user (`dev@payloadcms.com` / `test`) in the real `users` collection via `tests/helpers/seedUser.ts`.

The exception is `tests/int/i18n.int.spec.ts`, which only reads the message catalogues and runs without a database.

`BLOB_READ_WRITE_TOKEN` must match `vercel_blob_rw_<store_id>_<random>` — `@payloadcms/storage-vercel-blob` throws at config-build time on any other shape.

Playwright uses `channel: 'chromium'` — run `pnpm exec playwright install chromium` once.

## Generated files

- `src/payload-types.ts` — regenerated by `pnpm generate:types` (ESLint and Prettier both ignore it). Never hand-edit; fix the collection config instead.
- Admin import map — run `pnpm generate:importmap` after adding or moving admin components.
- `src/migrations/*.json` — drizzle snapshots, committed alongside each `.ts`.

## Schema changes

Migration history lives in `src/migrations/`. Create one with `pnpm payload migrate:create`; deploys run `pnpm ci` (`payload migrate && pnpm build`). The Postgres adapter sets no `push` flag — per the README, dev defaults to pushing schema directly, so a local schema change may not produce a migration file on its own. Always create one before shipping a collection/field change.

`migrate:create` drives an **interactive** drizzle prompt that asks how each conflicting column was created. It needs a real TTY, and Enter accepts the default ("create column"), which is almost always what you want:

```bash
(for i in $(seq 1 400); do printf '\r'; sleep 0.35; done | script -qec "pnpm payload migrate:create <name>" /dev/null)
```

Plain `yes ''` does not work — the prompts need `\r`, not `\n`.

## Architecture

One Next.js 16 app hosting both halves, split by route group:

- `src/app/(payload)` — admin panel and API routes. Intentionally **outside** the locale segment.
- `src/app/[locale]/(frontend)` — the public site (home, pages, posts, search, 404, accessibility statement).
- `src/app/[locale]/(sitemaps)` — locale-scoped `pages-sitemap.xml` / `posts-sitemap.xml` route handlers.
- `src/app/llms.txt`, `src/app/robots.txt` — unlocalized root routes, AI-crawler oriented.
- `src/i18n` — locale list, next-intl request config, typed `getDictionary`, and one `messages/<locale>.json` per locale.
- `src/payload.config.ts` — Payload config: collections (`src/collections`), globals (`src/Header`, `src/Footer`, `src/globals`), plugins (`src/plugins`), DB adapter, Blob storage.
- `src/migrations`, `src/access`, `src/fields`, `src/hooks`, `src/utilities` — shared Payload code.

Path aliases (from `tsconfig.json`): `@/*` → `src/*`, `@payload-config` → `src/payload.config.ts`.

## Internationalization

Locales are `en` (default), `de`, `fr`, `es`, declared in three places that must stay in sync: `src/i18n/config.ts` (`locales`), `payload.config.ts` (`localization.locales`, `i18n.supportedLanguages`), and one `messages/<locale>.json` file.

- **URL strategy is `as-needed`** (`localePrefix` is `''` for `en`, `/${locale}` otherwise). Every route lives under `src/app/[locale]/`, so English is served by **rewriting** the unprefixed path onto `/en` in `src/proxy.ts` — not by redirecting. `/en/...` canonicalises to `/...` with a 308, and unprefixed non-root paths negotiate `Accept-Language` first. Rewriting is what makes the root canonical URL actually resolve; a `NextResponse.next()` there 404s. Note the file is `proxy.ts`, not `middleware.ts` — Next.js 16 renamed the convention.
- Link builders and `getLocalizedPath` in `src/utilities/generateMeta.ts` must use the same rule, or you get two URLs per English page.
- **`next-intl` needs three pieces wired up**: `createNextIntlPlugin('./src/i18n/request.ts')` in `next.config.ts`, `unstable_setRequestLocale`/locale validation in `src/app/[locale]/layout.tsx`, and `NextIntlClientProvider` there for client components. Removing any one breaks every `useTranslations` call.
- **Never inline per-locale maps** (`{ en: '…', fr: '…' }[locale]`). That pattern silently produced blank German pages. Add a key to all four catalogues instead — `tests/int/i18n.int.spec.ts` enforces key parity.
- **`locale: locale as 'en' | 'de' | 'fr' | 'es' | 'all'`** is the cast Payload's generated types expect. Narrowing it to `'en' | 'es' | 'fr'` silently drops German.
- Admin `label` / `admin.description` maps must carry all four locales too, otherwise a German admin falls back to English.

## SEO / AEO

- JSON-LD lives in `src/components/schema/`. `ArticleMarkup`, `FAQMarkup`, `BreadcrumbMarkup` and `SpeakableMarkup` are wired into the Post and Page routes; `AEOSection` (`src/blocks/AEO`) renders the editor-authored `aeoSummary` / `answerBlocks` visibly and emits `FAQPage`. Adding a component here does nothing unless something imports it.
- `generateMeta` emits `alternates.languages` for all four locales plus `x-default`. Keep it that way.
- `next-sitemap.config.cjs` must reference the locale-scoped sitemap routes with an explicit prefix — `/pages-sitemap.xml` without one 404s. `generateRobotsTxt` is off because `src/app/robots.txt/route.ts` is the source of truth.

## Conventions and gotchas

- **Style:** Prettier config exists but there is no `format` script — `pnpm exec prettier --write .`. Settings: no semicolons, single quotes, `printWidth: 100`, trailing commas everywhere.
- **Always call tools through the package scripts.** Every script wraps itself in `cross-env NODE_OPTIONS=--no-deprecation` to suppress Payload/Node deprecation noise; running raw `next` or `payload` skips that.
- **Env:** `.env.example` → `.env`, needs `POSTGRES_URL`, `PAYLOAD_SECRET`, `BLOB_READ_WRITE_TOKEN`, `PREVIEW_SECRET`, `CRON_SECRET`, `NEXT_PUBLIC_SERVER_URL`. A `localhost`/`127.0.0.1` connection string switches the adapter to plain Postgres instead of Vercel Postgres.
- **Revalidation:** published content changes revalidate the frontend through `afterChange` hooks. Changing a redirect's `from` field requires a rebuild (the plugin says so in the admin description).
- **Seeding** from the admin panel's "Seed the database" button is destructive — it drops existing content.
- **Cron:** `vercel.json` hits `/api/payload-jobs/run` daily for scheduled publish; the endpoint accepts `Bearer $CRON_SECRET`.
- **RGAA:** `src/fields/link.ts` rejects non-explicit link labels ("click here", "hier klicken", …) in every language, surfacing the message in the editor's own admin locale.
